# Backend module map

Part of the agent manual. [AGENTS.md](../../AGENTS.md) is the entry point and
links every reference doc; this one holds the backend module map from
CLAUDE.md's "Architecture", moved there word for word on 2026-10-13 (only
relative links were re-based). Read it to find which Rust module owns
something, and whenever you add, rename or remove a top-level `src-tauri/src`
module: `scripts/check-module-map.mjs` (in `npm run test:scripts`) fails until
this map names every module and only modules that exist. Frontend modules are
mapped in [FRONTEND_MODULES.md](../FRONTEND_MODULES.md). Keep it current with
the code in the same change, as AGENTS.md asks.

### Backend module map

`session_settlement.rs` is the organization child that stores one-shot policies
in `session_settlement(session_key, policy JSON)`. Native sweeps check activity,
revision, successful completion, pins, snoozes, pauses, questions and live work
again in the transaction. `build_changes::settlement_pr` verifies exact bound
PR identity with read-only git/gh commands; unavailable evidence never settles.

`session_organization.rs` is a `session_store` child module. Its additive
`session_organization` table stores session key, pin, snooze deadline, settlement
reason, activity snapshot and integer revision. `list_conversation_organization`
and `organize_conversation` in `commands/sessions_api.rs` expose it to the UI.
Mutations compare revision and activity inside `with_write`; settled state uses
the existing `sessions.archived` bit. Snooze deadlines remain readable after
expiry so the UI can surface old due rows. New activity invalidates snooze and
settlement metadata, while pins survive. No automatic settlement runs here.

The paused AI company (assignments, employees, the restricted report and
workflow routes, the priority pause, company budget claims and Linear activity)
was removed 11-10 (COO rebuild L11; git tag `company-paused-20261110` keeps it).
Its 46 tables stay, inert, in databases that have them; nothing creates or reads
them except the CFO's one-time `company_settings` migration, and the pump ends
a row it queued once (`run_pump::removed_company_row`). Record:
company assignments.

`cfo/mod.rs` (COO rebuild L7) is the CFO every turn passes through: it decides
agent, model, effort and account, records the `Decision` with its reason in the
run manifest and receipt, and owns the `cfo_*` commands (and the inner
functions their `settings.cfo_*` COO actions share). Its
`cfo/settings.rs` keeps the policy in `cfo_settings` (migrated once from
`company_settings`), `cfo/job.rs` reads the job kind of a prompt,
`cfo/effort.rs` maps kinds to levels, `cfo/accounts.rs` holds the readings, the
reserve, holds and the soonest-reset account, `cfo/choose.rs` places a
subagent from the allowlist, and `cfo/budgets.rs` (L9) enforces the per-project
and per-subagent budgets (`cfo_subagent_budgets`). See
[CFO](../CFO.md).

`private_memory.rs` reads project-scoped provider scratch notes on an explicit
Library request. It never writes them; pinned exact passages become pending
promotion proposals through the ordinary safety scan.

`skill_learning.rs` queues grounded task lessons as pinned append proposals
for a used shared skill or a proposed new shared skill. Only Library's Save
applies one, through `skills::write_skill_file`, and Undo reverses it while
the skill is unchanged; fresh source checks preserve existing skill bytes.

`memory_maintenance.rs` owns per-vault usage/expiry metadata, pin and restore
controls, current-recall eligibility and the profile-size consolidation
proposal. Its state stays in app data; saved facts are never deleted.

`learning_capture.rs` owns the provider-neutral capture queue, idle and
long-chat triggers, coalescing and handover/context-boundary snapshots.

`memory_report.rs` (ME1, 2026-11-18) owns the memory change report each
capture run writes to `.hollow/memory-reports/<UTC day>.jsonl` (added,
updated, removed, skipped with a `Reason` code); `vault_learning` fills it.
See [vault](vault.md) "Memory candidates are versioned".

`session_search.rs` is session_store's full-text child module. It owns the
scrubbed FTS5 documents, per-turn dirty marks, the bounded refresh and
matched-turn context shared by sidebar, palette, agent and phone search, and
the startup integrity check (`verify`: FTS5 `integrity-check`, a damaged index
is dropped and re-marked for the backfill; chats untouched). See
[chat search](../CHAT_SEARCH.md).

`context_roots.rs` (CX3) owns the context layers' clone roots
(`context-roots.json` in app data), this machine's slug
(`~/.config/hollow/machine.json`), the path rules (no symlink anywhere, nothing
outside the root, `O_NOFOLLOW` reads) and the Settings status read; tested in
`context_roots_tests.rs`. Read by `context_layers.rs`. `context_pins.rs` (PX3, 11-16) reads the memories marked `pinned: true` into the digest's `personal/pinned.md` section (1,500 bytes, an over-budget pin named, not loaded) and, once per rule a couple of minutes after launch, files a learning-proposal card to promote each of three safety memories to `me/Guardrails.md` (`context-promotions.json` in app data records the offers). See
[Context roots](../DIRECTORIES.md#context-roots-cx3-2026-11-13).

`context_layers.rs` (CX4, CX5, read side) builds the context layers' sections
the context compiler appends to the operator profile block: this machine's
`home/<slug>.md` from the personal clone (4 KB) and the org clone's `INDEX.md`
or a generated top-level listing (2 KB), both read through `context_roots`, and (PX2, 11-16) a generated index of the personal clone's memories and learnings (2 KB, `personal_index`: one line per file from its `description:`, grouped by type, never written, an explicit closing line when it overflows);
it also runs the org clone's `git pull --ff-only` timer (30 minutes, its own
thread, 60 s timeout), reads the clone's files as retrieval kind `org`
(`org_passages`, CX5b) and builds the Claude rules that refuse writes there
(`write_rules_for`; what they can't refuse is `ORG_BLOCK_LIMITS`). `health` (PX7) is the capability doctor's read of the personal clone: whether the vault's and the clone's `me/` agree (hash compare) and how fresh the home file's `Last checked` date and the memories' `verified_at` / `valid_until` are; it rides `Diagnostics.contextHealth`.

`context_stale.rs` (ME2, 11-18) is the one staleness rule for memory and home files (PX4's `verified_at` / `valid_until`, PX7's 180 days; an undated home file by `Last checked` over 30 days), used by `health_in` (its `homeStale` is what the doctor shows) and by `context_layers::sections`: the personal index lists a stale memory last, labelled, under "Needs recheck"; a stale home file says so in its lead; each stale file becomes one `memory_recheck` review card (fingerprint = file and stale date, at most `OPEN_CAP` open, offered on its own thread).

`context_propose.rs` (CX8) is `context.propose_org_change` and
`context.merge_org_change`: validates and scans the files (`scan_rules` org
layer, `memory_guard`), then, in a throwaway clone of the org remote, branches,
commits (`sync_commit_message`, actor = login and the caller's own session
key), pushes and opens the pull request with `gh` (template and scan output
filled in). `gh api user` against `CODEOWNERS` (last `*` line; `.github/`, root,
`docs/`) decides owner or teammate. `merge_own` squash-merges an owner's PR only
for an attended chat (depth 0, not unattended): up to 6 looks 10 s apart, the
head, branch and base must equal what was pushed, every required check of the
base branch (protection API plus ruleset `required_status_checks` rules, 404 =
none, any other error stops; a rule naming an app needs a CheckRun) must be
reported and SUCCESS, any present check final and passing (latest entry per
name), an empty rollup waits when the clone has `.github/workflows/`, then `--admin --match-head-commit <sha>`. A
PR left waiting is merged later by `merge_org_change` (same checks; the URL must be a pull request of the org clone's origin repo
and the record's, `-R <owner>/<repo>` on every gh call, record must show an
owner line; idempotent, no second `merged` line). Any other PR waits labelled "needs owner
approval". The record `context-org-prs.jsonl` in app data gets an `opened` line
per PR and a `merged` line when the later step merges. All `git`/`gh` calls go
through the `Runner` trait and pauses through `Env.sleep` (tests: scratch bare
repo, fake `gh`).

`context_org_digest.rs` (CX8b) is the `org-digest` `nightly` window job: owner
PRs from the record that merged and were never listed (watermark
`context-org-digest.json` beside it) go one line each into
`workspaces/main/outputs/org-changes/<date>.md`, then one in-app notification
opens it. Teammates' and still-waiting PRs are left out; nothing new, nothing
written.

`sync_engine.rs` (CX6a) is the context sync engine: roots (personal now, the
vault and org later), a git directory in app data with the vault as work tree,
the allow-list, the scan before every commit, `merge-tree` merges that keep
both versions of a clash, the offline queue, the quiet timer, the off switch
and four commands; tested in `sync_engine_tests.rs`. See
[Context sync engine](../DIRECTORIES.md#context-sync-engine-cx6a-2026-11-14).
`sync_vault.rs` (CX6b, a child module of it) is the vault root: the built-in
ignore manifest, the generated `info/exclude`, the text-only and 1 MB checks
and its staging, plus `configure_vault_sync`; tested in `sync_vault_tests.rs`.
`sync_files.rs` (V4, N15) fetches one write-once binary the vault root keeps
out (media, binary and data files, over 1 MB; never text, dot, personal or
`tasks/` paths) from the runner over ssh when asked (`fetch_peer_file`, never
overwrites; `peer_files` lists): a Perl peer program, resumable part files,
`configure_file_copy` (user-only, the peer's vault path) and
`file_copy_status`. The retired timed two-way copy (planner, cycle,
`.hollow-files.json`) stays unused and tested; tested in
`sync_files_tests.rs`. See
[Binary copy](../DIRECTORIES.md#binary-copy-between-the-macs-v4-2026-11-15).

`sync_clash.rs` (CX6c, a child module too) keeps one clash record per file in
each root's state, lists the cards (`sync_clashes`) and applies Keep mine, Keep
theirs, Keep both, Edit and Done (`resolve_sync_clash`); tested in
`sync_clash_tests.rs`.

`context_settings.rs` (CX17) backs Settings, Sources, Context: one read of
every layer row (`context_layers_status`, also `settings.context_layers_status`),
the org access check (`git ls-remote`, no prompt), Local only, and the
person's clone folders and machine name. See
[Settings, Context](../DIRECTORIES.md#settings-context-cx17-2026-11-15).

`mac_context.rs` + `mac_context_tests.rs` (two-Macs F3) offer "Connect this
Mac's context" once per Mac pair (this Mac's id and a paired Mac's, or
`runner:<alias>`; Not now returns after 14 days) and run its Connect: clone
the personal and org repos into their clone roots, name this Mac, write
`home/<slug>.md`. See
[Connect this Mac's context](../DIRECTORIES.md#connect-this-macs-context-f3-2026-11-15).

`leak_checks.rs` (CX10) holds the leak-check switch (`context.leakChecks`,
flag until CX10b), `check_write` for context writers, the flags ledger
(`context.leak_flags`), the local pre-push context check
(`context_check_status`, `context_install_check`, `context_remove_check`,
with a scanner copy in app data) and the monthly `context.audit`. See
[Leak checks](../DIRECTORIES.md#leak-checks-cx10-2026-11-15).

`folder_abstracts.rs` (CX23) builds a per-folder abstract and overview for
project workspaces and org sections bottom up (key: content or children's
abstracts plus `PROMPT_VERSION`), behind the `AbstractModel` seam, into a
derived index in app support; off by default (`context.folderAbstracts`). See
[Folder abstracts](../DIRECTORIES.md#folder-abstracts-cx23-2026-11-18).

`this_mac.rs` generates the shared machine note beside `hollow-slot` from
detected hardware, build paths, the runner (read by placement's own rule,
`remote_session::runner_setting`) and the slot source, and renders the
runner's own note that remote preparation installs.

`project_agents.rs` derives each non-built-in project's provider-neutral main
conversation key, validates its folder/ownership at queue acceptance and admission,
and supplies its concise role context. No persistent process or new database
schema is implied. See the client comparison.

`project_card.rs` (PC1, 11-18) checks a project's architecture card,
`outputs/PROJECT_CARD.md`, written by an agent from the code: the versioned
card prompt (`prompt-version: N` on line one), the card's key (`commit:` and
`prompt_version:` frontmatter, the commit read from the working folder's
`.git` files without spawning git), the required sections (Purpose, Modules,
Entry points, How to run, Risks) and the stale flag. Its status and text ride
the `<hollow-workspace>` envelope as `projectCard` (read first) for a
workspace with a connected repository or a card; `workspaces.project_card`
runs the check on demand. Hollow never writes the card. SD1 (11-18) adds an
optional design facet: a card's `design:` key links `outputs/DESIGN.md`, a brief
of at most 2 KB written from styling source under its own versioned prompt
(Theme, Colors, Typography, Components, Layout), checked only when linked and
shown on the card's status line; UI marker files only steer the action.
`first_connect.rs` (BI7, 11-18) is the describe-only first connect: creating a
build workspace from an existing repository writes `outputs/PROJECT_CARD_DRAFT.md`
in the workspace (never the repository) with facts read from files, run hints
and a "Needs attention" list (each item with a next step), plus a tree
fingerprint of the repository (path, type, size, mtime, ctime, inode, mode;
`.git` left out except its `index`, `HEAD`, `config` and `hooks/`) taken just
before `git worktree add` and after the read, recorded as "Nothing changed"
with both digests or flagged loudly. The describe step's one git call is
`status` with `--no-optional-locks`; the connect around it also runs `git
fetch` and `git worktree add` (the repository's own hooks), and the draft says
so. A card that isn't fresh points at the draft.

`project_workers.rs` validates explicit worker batches from global/project
main agents, retains per-run retry results, and queues ordinary local child
chats through `app_sessions`. It does not own resource or admission policy.

`pdf_preview.rs` admits scoped PDFs and renders bounded read-only page PNGs
and text through PDFKit, used by Preview and Results. Main-webview command
plumbing lives in `commands.rs` (two concurrent readers).
Its scoped read (`read_scoped`: roots, hidden and secret folders,
extension, signature, size cap, unchanged while read) also guards
`office_preview.rs` (B1b, ENG-104; UN1 adds per-row formulas): Word, Excel and PowerPoint text for the
Preview pane as parts (paragraphs, slides, sheet grids of at most 200 rows
and 20 columns) from `doc_text` and `xlsx_cells`, every cut listed.

`window_state.rs` is the pure main-window visibility/focus/minimized/tray policy.
`lifecycle.rs` collects native observations and reconciles the tray flag;
navigation and approval cards share that snapshot with distinct wait policies.

`calendar_source.rs` owns the app-local Agenda source setting, fakeable reader,
coverage mapping and occurrence identity. `calendar_source/native.rs` reads
EventKit on a blocking thread; only the explicit source command requests access.
Mac attendees travel with occurrences and bypass the Graph attendee cache.

App presets: `app_icon_presets.rs` (embedded exact-size PNGs and preset records;
Cut Glass is no override). See [Custom icons](../CUSTOM_ICONS.md).

and runtime Dock/menu-bar/window artwork). Person-only adapters: `commands/custom_icons_api.rs`.
Generate a logo: `logo_options.rs` (overhaul H2: one tool-free one-shot on the agent the window picked,
metered `logo_options`; keeps the SVGs `custom_icons::prepare` accepts; `generate_logo_options`, user-only;
`cancel_logo_options` stops one by request id through inline AI's stop table, overnight 11-13 S2).
See [Custom icons](../CUSTOM_ICONS.md).

Meeting recap: `meeting_recap.rs` (user-only finished-meeting reader, bounded transcript,
one tool-free writer, checked Review proposals and saved paraphrased page).

Grok ACP transport: `acp_client.rs` (OC1, 2026-11-18: one Grok chat turn over the Agent Client Protocol
as a pure state machine; `initialize`, `session/new` or `session/load`, config options, `session/prompt`; ACP

Codex steering transport: `codex_app_server.rs` (steering PR 3: one Codex chat turn over
`codex app-server` as a pure state machine; handshake, `turn/steer` and `turn/interrupt` writes, server lines
turned into the `codex exec --json` lines `parse_codex` reads, server requests declined; tests in

(`steering::PipeMsg::Steer`). Every other Codex run still uses `codex exec`.

Shared Codex owner: `shared_codex.rs` (SE9: account-environment pools, global
RPC ids, thread-scoped config/grants, inherited-fd relay, interrupt and crash
fan-out, bounded idle lifetime; [contract](../SHARED_CODEX.md)).

Canvas item copies: `canvas_items.rs` (saved source/project, bounded rows,
heading placement and preview-bound shared-doc CAS), reached only through
the main-window commands in `commands/canvases_api.rs`.
