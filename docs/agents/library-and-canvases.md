# Library and canvases

Part of the agent manual; [AGENTS.md](../../AGENTS.md) is the entry point. Canvases' one current reference is [docs/CANVAS.md](../CANVAS.md).

## Library

- Library starts on Results unless Notes or Recordings was explicitly saved; only view-tab choices persist. See [surface contract](../reference/surfaces.md).
- Results is one All/Files/Canvases list (`libraryResultsModel.ts`), joined with canvas-store metadata keyed by workspace and file/canvas. Ordinary files open in Preview. `canvasCompareMode.ts` consumes each Compare request once across remounts; Compare data passes into `openCanvasGallery` only after navigation accepts.
- `libraryCanvasListing.ts` coalesces refreshes behind six readers and deduplicates hung reads until IPC settles; file rows paint independently so a hung canvas store cannot block them. Failed refreshes keep last-good summaries with a stale notice; successful empty reads remove entries. At most 24 previews are eligible, two reserved for a selected detail. See [Canvas gallery](../reference/surfaces.md#canvas-gallery-overnight-10-1112-f3).
- Recording transcript search is local over loaded text; no audio or connector request runs on typing.

## Canvases

- A canvas is a `hollow-canvas` fence rendered in a sandbox (scripts, no network), talking through bridge v1, stored under `outputs/canvases/`. Diagrams are canvases using the kit's `hc-flow`; whiteboards are gone and an old board fence shows as JSON under a notice.
- Ask-canvases never send on their own: Hollow's Send under the frame sends the answers as the next message. The ask lock ignores a local user bubble until queue acceptance, a run id or restored status exists; a failed Send leaves every copy editable.
- Scripted artifact links need host confirmation, and the runtime removes WebRTC before agent scripts ([Windows](../reference/architecture.md#windows)).
- Canvas state retries keep the original edit time and revision; CAS refreshes never apply an old frame's edit to a newer revision. Pin updates verify revision bytes/hash and the existing pin.
- Saved item copies use the host-only dialog (frames cannot open it); confirmation compares the whole prospective document with shared-doc CAS, and a conflict keeps concurrent edits. See [canvas item copies](../CANVAS.md#copy-canvas-items).
- Saved canvases can be pinned to Work with read-only local scalar bindings ([Pinned live canvases](../CANVAS.md#pinned-live-canvases-overnight-2026-10-1213-f1)). Export: [Canvas export](../CANVAS.md#export-a-canvas-as-image-or-pdf). Palettes: [Workspace canvas look](../CANVAS.md#workspace-canvas-look); unsupported or alpha colours report unmeasured contrast.

## Canvas kit and texture

- Kit assets are generated by `kit:build` (`scripts/build-canvas-kit.mjs`); saved kit@1 markup stays compatible. See [Canvas kit](../CANVAS.md#kit1-and-kit-ask).
- Canvas root `texture` is presentation only: `canvasFrameBody` carries recognized requests into display/export bodies without changing saved source or answers. The sandbox's frozen `hollowCanvas.textureAllowed` defaults false and only a parent motion/presentation message enables it. Kit renderers use `textureOf`; functional contrast hatching is separate.
- Texture never changes data: charts keep exact values, boundaries, gaps, tables and keyboard paths; text and controls sit on solid plates. `watchTextures` shares one observer until the last graphic disconnects. No scroll listener or animation drives material.
