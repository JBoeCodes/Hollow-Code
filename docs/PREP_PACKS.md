# Meeting prep packs and recaps

## Meeting recaps

Calendar events come from the Agenda source in Settings → Connectors. All three
prep/recap reads use the same view. Native attendees come with their occurrence,
with the calendar account's current user removed; nil is unknown and [] is known
empty. They never use Microsoft's account identity or attendee cache. Off and
denied access report their actual state. See [Calendar sources](reference/architecture.md#calendar-adapter-constraints).

**Recap** appears on past timed meetings in Today and Agenda (not cancelled or all-day), and
**Recap the meeting** on a linked recording in Library. The same lazy dialog handles prep and recap;
there is no agent action. `meeting_recap.rs` owns the user-only command. A kept recap opens without
reading Calendar, Plaud or a model. Write it again checks the saved note and asks before replacing edits.
The shell imports only `store/prepPackOpen.ts`; the request state/loader lives with lazy meeting views.

The finished Calendar event is found within twelve hours of the supplied search centre. New picker
links preserve the known start in optional `eventStart`; changing the linked event clears it. Older
links use the recording's date at local noon to search Calendar, never as an asserted meeting start.
With Calendar unavailable or the linked event absent from its window, only an existing explicit link
allows a recap; its saved title/start are used (start stays empty if unknown), and attendees say they couldn't be read.
Cancelled/future events returned by Calendar are refused. Without both a stored start and recording
date, the person is sent to Agenda. The picker lists the meeting day's recordings, looking back age + 1 days (at most 60);
unreadable/incomplete Plaud data is an error, never a verified empty day. No link means no model call
or file write. Choosing a recording atomically retains its workspace and kept-copy metadata.

One tool-free, provider-neutral completion (`meeting_recap`, 240 seconds) reads whole transcript
segments within extraction's 120,000-character limit, including label overhead. The recap discloses
the first omitted timecode. A segment larger than the limit stops before any paid call. The writer
returns a summary, cited questions and proposals; extraction checks proposal evidence against the
specific segment. The page contains paraphrases and timecodes, not evidence quote fields; copied
fields matching normalized evidence/segments or eight consecutive transcript words are omitted,
ignoring case and whitespace. Short proposal titles retain their wording (only the eight-word
rule applies there); short-quote checks apply to summary/questions. This is a bounded copy check,
not proof of original wording. Review retains evidence for checking.

Pages live in the linked workspace's `outputs/recaps/`, else the best match, else Main. Frontmatter:
`type: meeting-recap`, `meeting-id`, `recording-id`, `start` (empty if unknown), `workspace`, `generated`,
`hollow-written-sha256` (the exact generated bytes excluding this field).
The source line names the recording, id and read time. A rewrite keeps its original path. Concurrent
requests for the same canonical vault/event fail before paid work; retries can reopen the saved page.

`extract::queue_checked` uses the same local/Jev dedup, identity questions and ledger as normal
extraction. The source key is `plaud:<id>`; unchanged transcript rewrites add no proposals. Existing
Recordings **Create tasks** is a separate local parser (no shared ledger); a later recap dedups against
those tasks and kept-transcript proposals. The reverse order remains a gap: Create tasks does not
check pending recap proposals, and different model paraphrases may fall below the local match threshold.
A queue error remains retryable, and save failure
after queuing cannot duplicate proposals. See [Extraction](EXTRACTION.md).
Offline filenames use the supplied meeting day, not the click day. A missing linked workspace falls
back to the matched workspace/Main without recreating a deleted workspace. Saved paths are checked
against the canonical vault before reads and again after asynchronous generation.

Synthetic tests cover picker/kept/rewrite behavior, bad quotes, truncation and offline metadata.
Native recap dialog, real Plaud timecodes, Review, VoiceOver and live provider behavior require hand
verification after a separately requested install.

## What the person sees

- **Prepare** on Today's calendar rows (upcoming, timed), or **Prep pack** in the Agenda's event detail (not cancelled,
  not all-day, not over, starting within 24 h). The dialog shows "Prep: <subject> · <when>". While the pack is written,
  pulsing dots and "Reading who's coming…"; on error, the reason and **Try again** when no pack is available.
- **The page** (Markdown, also saved as a note):
  - **Who's coming:** each attendee in bold, with their role and a link to their people note, and under them the open
    commitments both ways.
  - **Related work:** each matched workspace's next step and open items, and its newest Result.
  - **Earlier notes:** up to 3 notes or recordings sharing the meeting's distinctive words.
  - **Open questions**.
  - **Talking points:** each one cites `[n]`.
  - **Sources:** a numbered list.
  - A closing line says the questions and points are the agent's, to be checked.
- **Footer:** "Kept from earlier" or "Written now", with the path; **Write it again**; **Open as a note**; **Done**.
  esc closes.

## How it works

- **Finding the meeting:** a kept pack is found first by its frontmatter `meeting-id` in any workspace's
  `outputs/prep/` (`find_kept`), with no calendar read, so a meeting that has already started still opens its pack.
  Otherwise `prep_pack(meetingId, regenerate)` and `agenda.prepare_meeting` read
  `meeting_prep::for_this_mac(vault, 24)`; each meeting now carries its calendar `id`. A meeting not in the next 24
  hours, or a calendar that isn't connected, is an error that says so.
- **Attendee readiness (overnight10-12 A8):** the meeting read already awaits Calendar's bounded attendee fetch. If
  coverage is still `None`, a new pack or rewrite stops before any paid completion or pack write; `Some([])` means
  known empty and is valid. Existing packs remain readable without Calendar. Older partial packs are preserved;
  use Write it again after attendees become available.
- **Concurrent requests:** Prepare and Write it again for the same canonical vault/event id share one active
  app-process result, including errors, when the meeting snapshot, rewrite intent and expected revision agree. A rewrite never inherits a merely kept pack; a ticking countdown does not make a new snapshot. An ordinary Prepare still returns a saved pack when a concurrent rewrite fails. A later request can retry or explicitly regenerate. Dropping the prepare future releases the coordinator lock; unrelated meetings/vaults are independent. Weak entries retain no result after all callers finish.
  This is in-process coordination, not a lock between separately launched Hollow processes.
- **The dossier** (`dossier`) is deterministic:
  - Attendees plus the organizer; "+N more" is dropped.
  - Each attendee's people note matches by full name or file stem; a one-word attendee name ("Pat") may match the one
    person with that first name. "Pat Jones" with no note of his own matches nobody.
  - Open commitments match by the person's note or by exact full name (both directions); a counterparty "Pat" isn't
    every Pat.
  - People notes are `[[wikilinks]]`, so they open as notes and never navigate the window.
  - The workspaces come from `meeting_prep`'s matches.
  - Earlier notes come from `vault::search`, leaving out `outputs/prep/` and `people/`, in up to three kinds of
    search (ENG-39, 2026-11-14): the subject's distinctive words; each attendee's full name as an exact phrase (a
    first name alone is never searched); and the invite body's longest distinctive words (`bodyPreview`, one search
    per word). A word shorter than 4 letters, or from the body, must stand as a whole word in the note it pulls: the
    vault search lets a 1 to 3 letter term begin a word, so `nat` used to find "native".
  - The pack is filed in the workspace whose whole title is in the meeting title, whatever its status (a
    non-current one is never ranked, but a title that names it decides); else the best ranked match; else Main.
  - Each item is a numbered source.
- **The agent's part:** the default agent (any provider, tool-free, 150 s, metered `prep_pack`) gets the numbered
  sources, fenced as data. It returns `{openQuestions, talkingPoints[{point, cites}]}`. A point citing no real source
  is dropped; at most 5 questions and 6 points.
- **Saving:** to `workspaces/<best match>/outputs/prep/<date>-<slug>-<6 hex of the event id>.md`, else to the Main
  agent's workspace. Two meetings with one subject on one day get two files. An existing pack is returned unless
  `regenerate`; its returned path/workspace is the actual saved location even if matching changes. A rewrite retains that path when the date, title or matched workspace changes, preventing a second stale copy. Both kinds of note store `hollow-written-sha256` just after the opening frontmatter delimiter. Returned `contentHash` covers the whole file; `edited` compares the stored fingerprint, with missing provenance treated as unknown. The UI reads the current note before rewriting and confirms edited/unknown content. `expectedHash` binds that choice to exact bytes; a stale choice refuses before paid work. A final compare-and-swap preserves edits made during generation, and a new note never replaces an existing path. Safe-path validation rejects a saved path escaping the vault. `agenda.prepare_meeting` is `Lease::Outside`, so the model call never runs under the History lock.
  Its model call is metered to the calling run, so a check-in's packs count toward the Main agent's day. An unattended
  turn may write a pack but never pass `regenerate`, so it never overwrites one the person edited.
- **The Main agent:** see [COO.md](COO.md), "Meetings in the next hour". `agenda.prepare_meeting` is on
  the unattended safe list.

## Limits

- Legacy notes without a writing fingerprint remain readable, but agent regeneration refuses them. Open the meeting's Prep dialog and choose Write it again to review the replacement confirmation there.
- Recap proposals queue before the final note write. A concurrent note edit can therefore leave checked proposals in Review while the note save refuses; the existing extraction ledger keeps retry idempotent.
- Last interactions with a person come only through their people note and commitments; there is no message history
  (Hollow has none).
- Recording summaries appear only when vault search finds them by the meeting's words.
- Closing the dialog does not cancel the native command’s already-started writer (unchanged). The coordinator cancellation test drops its fake prepare future; it does not establish native provider process cancellation.
- Calendar attendee failures can require an access repair; the error does not promise that waiting alone will resolve them.
